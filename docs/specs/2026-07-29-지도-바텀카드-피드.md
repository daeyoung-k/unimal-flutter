# 메인 지도 바텀카드 피드 (앱)

- 작성일: 2026-07-29
- 상태: 설계 확정 / 구현 대기
- 대상: `lib/screens/map/map_naver.dart`, `lib/screens/map/feed/` (신규)
- 서버 계약: `unimal-server` `docs/specs/2026-07-29-지도-바텀카드-피드-api.md`
  (**서버 미구현** — `.kt` 전수 검색 0건, 문서만 존재)

## 1. 목표

메인 지도 하단에 상시 바텀시트를 두고, 지도를 누르지 않아도 "지금 이 지역에 뭐가
올라왔는지" 알 수 있게 한다. 당근마켓 동네지도의 카드 피드와 같은 역할이다.

지금은 마커를 하나하나 눌러야 콘텐츠를 소비할 수 있다. 마커는 탐색 도구지 소비
도구가 아니다.

내지도(`my_story_map_screen`)에 이미 `DraggableScrollableSheet` 기반 하단 목록이
있으므로 그 패턴을 가져오되, 메인 지도의 제약(루트 네비바 + 기존 마커 카드)에 맞춘다.

## 2. 데이터 계층

### 엔드포인트

`GET /board/map/feed?latitude=&longitude=&zoom=` — 서버 스펙 그대로.

응답은 섹션 배열(`LATEST` / `HOT` / `NEARBY`)이고, 섹션당 최대 10건 + `hasMore`.
서버가 3건 미만 섹션을 아예 제외하고, 섹션 간 중복도 제거해서 내려준다. 앱은 **받은
섹션을 순서대로 그리기만 한다** — 분기 로직을 클라이언트에 두지 않는다.

### 기존 패턴을 따른다

`getMapLocationPosts` 는 `board_api_service.dart` 에 있고 그 모델 `MapPost` 는
`service/map/models/` 에 있다. 같은 선례를 따른다.

- `board_api_service.dart` → `getMapFeed({latitude, longitude, zoom})` 추가
- `lib/service/map/models/map_feed.dart` 신규 —
  `MapFeedResponse` / `MapFeedSection` / `MapFeedItem` / `MapFeedSectionType`

### 응답 키는 snake_case — 구현 중 방향 전환 (2026-07-29)

**처음에는 이 API 를 camelCase 로 설계했다.** 근거는 "Jackson 기본이 camelCase 라
`@JsonProperty` 노가다가 없어진다" 였고, `unimal-server` 의 피드 API 스펙 문서도 그렇게
적혀 있다.

구현 중(Task 3 진행 시점) `CLAUDE.md` 에 네이밍 규칙이 명문화되면서 방향이 바뀌었다:

> API 응답 JSON 키는 **snake_case**. 코드 안에서는 camelCase 로 쓰고
> **직렬화 경계에서만 변환한다.**

따라서 **Dart 프로퍼티는 camelCase 로 두고 `fromJson` 의 키 문자열만** snake_case 로
읽는다.

| Dart 프로퍼티 | JSON 키 |
| --- | --- |
| `boardId` | `board_id` |
| `thumbnailUrl` | `thumbnail_url` |
| `streetName` | `street_name` |
| `profileImage` | `profile_image` |
| `likeCount` | `like_count` |
| `replyCount` | `reply_count` |
| `createdAt` | `created_at` |
| `hasMore` | `has_more` |

한 단어 키는 그대로다: `type` `title` `content` `dong` `latitude` `longitude` `nickname`
`items` `sections`.

서버는 **클래스 레벨 `@JsonNaming(SnakeCaseStrategy)`** 로 만든다. 필드별
`@JsonProperty` 나열은 금지다 — 필드를 추가할 때 어노테이션을 빼먹으면 그 키만 조용히
camelCase 로 새고 앱에서 null 로 읽히는데, 클래스 레벨 하나면 그 사고가 구조적으로
불가능하다 (`unimal-server/CLAUDE.md`).

> **후속 작업**: `unimal-server` 의 `docs/specs/2026-07-29-지도-바텀카드-피드-api.md` 는
> 아직 camelCase 로 적혀 있다. 서버 구현 시 그 문서도 정정해야 한다.

참고로 기존 앱 모델의 표기는 갈려 있다(실측 2026-07-29): `MapPost`·`NoticeModel` 은
snake_case, `BoardPost`·`FileInfo`·`LikeInfo` 등은 camelCase, `ReplyInfo` 는 혼재
(`profile_image` 만 snake — 서버 `ReplyDto.kt` 와 일치하므로 버그는 아니다). 기존 API 를
snake_case 로 수렴시키는 것은 앱 동시 배포가 필요하므로 별도 작업이다.

### 모르는 섹션 타입은 건너뛴다

`MapFeedSectionType` 에 `unknown` 폴백을 둔다. 서버가 나중에 섹션을 추가해도 구버전
앱이 깨지지 않고 **그 섹션만 무시**한다. 앱 배포 없이 서버가 섹션을 늘릴 수 있어야
한다는 것이 이 API 설계의 전제다(헤더 문구도 서버가 내려준다).

### 주소 파라미터는 넘기지 않는다

`NEARBY` 섹션은 행정동(`siDo`+`guGun`+`dong`)이 필요하다. 그런데 지도 화면은 현재 동을
모른다 — `GeocodingApiService` 는 글 작성 화면(`share_card_sheet.dart`)에서만 쓴다.

앱이 역지오코딩을 먼저 하면 **순차 2 RTT** 가 되어 "지도 진입 직후 1 RTT" 라는 이
API의 존재 이유가 깨진다. 서버 스펙이 이미 gRPC 역지오코딩 폴백 + 캐시를 설계해뒀으니
그 폴백을 쓴다.

나중에 지도 화면이 동을 알게 되면 파라미터만 추가하면 된다 (서버는 앱이 넘긴 값을
우선한다).

## 3. 상태 소유 — 시트가 자기 데이터를 갖는다

두 방식을 검토했다.

| | `map_naver` 가 피드 상태 보유 | **시트가 자기 상태 보유 (채택)** |
| --- | --- | --- |
| `map_naver` 증가분 | 필드 5~6개 + fetch 메서드 | notifier 1개 + 위젯 1개 |
| "열렸을 때만 조회" | `map_naver` 가 시트 열림 상태를 알아야 함 | 시트가 자기 컨트롤러로 판단 |

`map_naver.dart` 는 이미 2,900줄이다. 두 번째를 택한다.

- `map_naver` → `ValueNotifier<MapFeedQuery?>` 소유. **마커 재조회가 성공한 시점**에
  갱신한다(이미 그 지점에서 `_lastQueriedTarget` 등을 갱신하고 있다).
- `MapFeedSheet` → notifier 를 듣고, **시트가 펼쳐져 있을 때만** fetch 한다.
- `DraggableScrollableController` 는 `map_naver` 가 소유한다 — 마커 탭 시 시트를
  접어야 하므로 외부에서 제어할 수단이 필요하다.

### 재조회 시점

기준은 **"보여줄 내용이 있는가"** 다:

| 상태 | 마커 재조회 성공 시 |
| --- | --- |
| 내용 없음 (`sections` 비어 있음) | **무조건 조회** — peek 여부 무관 |
| 내용 있음 | **시트가 펼쳐져 있을 때만** |

"펼쳐져 있음"의 정의: `DraggableScrollableController.size` 가 peek(0.15)보다 유의미하게
큰 상태. 판정 임계값은 `peek + 0.05` 로 두어 스냅 애니메이션 도중의 중간값이 오판되지
않게 한다.

### ⚠️ 이 조건을 "첫 1회만" 으로 만들면 안 된다

처음 설계는 "진입 후 **첫 1회**는 무조건" 이었다. 그건 **첫 조회가 실패하는 순간 피드를
영구히 죽인다** (2026-07-29 리뷰에서 발견):

1. 조회 실패 → 내용 없음 → §8 규칙에 따라 시트 미렌더
2. → `DraggableScrollableSheet` 이 안 만들어져 컨트롤러가 **부착되지 않음**
3. → `size` 접근이 던지고 "접힘" 으로 처리 → `_isExpanded` 영원히 false
4. → "첫 1회" 를 이미 썼으므로 이후 모든 조회가 펼침 게이트에 막힘

사용자가 콘텐츠 있는 지역으로 계속 이동해도 다시 조회하지 않는다. **서버 미구현 상태
(목 플래그 off)에서는 반드시 발생**하고, 서버가 붙은 뒤에도 진입 시 일시적 네트워크
실패 한 번으로 재현된다.

핵심은 §8("내용 없으면 시트를 렌더하지 않는다")과 이 재조회 규칙이 서로를 잠근다는
것이다. **내용이 없는 동안은 게이트를 우회해야** 복구 경로가 생긴다. 조회 폭증은
걱정할 필요 없다 — 이 알림은 마커 재조회 성공 시에만 오고, 그 재조회는 디바운스
300ms / 뷰포트 30% 이동 / 30초 신선도로 이미 조여져 있다.

peek 상태에서는 보이는 게 첫 섹션 카드 상단뿐이라 갱신 가치가 낮다. 시트를 올린 상태에서
지도가 충분히 이동하면(= 마커 재조회가 일어나면) 그때 갱신한다. 결과적으로 API 호출량이
지금과 사실상 같다.

`MapReloadPolicy` 는 건드리지 않는다. 특히 **피드 시트를 `isInteractionOpen` 에 넣지
않는다** — 넣으면 시트가 열린 동안 지도 자동 재조회가 멈추고, 피드도 함승할 대상이
없어져 영원히 갱신되지 않는다.

## 4. UI

```
lib/screens/map/feed/
├── map_feed_sheet.dart        # DraggableScrollableSheet + fetch/상태
├── map_feed_section_row.dart  # 섹션 1개 (헤더 + 가로 카루셀)
└── map_feed_card.dart         # 카드 1장
```

### 시트

- `initialChildSize: 0.15`, `minChildSize: 0.15`, `maxChildSize: 0.9`,
  `snap: true`, `snapSizes: [0.15, 0.9]` — **peek 이 하한이다.** 사용자가 시트를 완전히
  없앨 수는 없다(상시 노출이 이 기능의 전제).
- peek 에서 핸들 + 첫 섹션 헤더 + 카드 상단만 보인다. 지도가 거의 가려지지 않고,
  좌우 하단 버튼(내 위치 / 내 지도, `bottom: 45`)도 그대로 살아 있어 재배치가 없다.
- 세로로 섹션을 쌓고 **섹션별 가로 카루셀** (넷플릭스 행 패턴)
- 핸들·헤더를 같은 스크롤뷰 안에 둔다 — 내지도 주석의 교훈:
  `DraggableScrollableSheet` 는 controller 가 붙은 스크롤러로만 끌린다. 핸들을 시트
  바깥에 두면 핸들을 잡아도 시트가 안 끌린다.
- 섹션 헤더: 서버가 준 `title` + `hasMore` 면 `>` 표시. **탭 동작은 없다**
  (섹션별 더보기 페이지네이션은 서버 스펙에서도 범위 밖).

### 광고 자리

이번 범위에서 광고는 **제외**한다. 대신 섹션 렌더러가 **위젯 리스트를 조립하는 형태**로
둬서, 나중에 광고를 섹션 사이에 끼우는 일이 리스트에 한 항목 추가하는 것으로 끝나게
한다.

현재 `AdBanner`(배너 포맷)는 구현돼 있으나 어느 화면에서도 쓰이지 않고
(`profile.dart` 에 주석 처리), `AdService` 에는 배너 unit ID 만 있다. 글 카드와 톤이
맞는 네이티브 광고를 쓰려면 ad unit ID 발급 + Android/iOS `NativeAdFactory` 등록이
선행되어야 한다 — 별도 작업이다.

## 5. 카드 탭 → 확장카드 (카메라 이동 없음)

피드 카드를 누르면 **그 자리에서 확장카드가 올라온다.** 지도 카메라는 움직이지 않는다.

### 피드 아이템만으로는 확장카드를 채울 수 없다

서버가 캐시 가능하게 만들려고 `isLike`/`isOwner`/`score` 를 일부러 뺐고, 이미지도
`thumbnailUrl` 한 장만 온다. 확장카드는 좋아요 상태·전체 이미지 캐러셀·본인글 메뉴가
필요하다.

→ **탭 시 `getBoardDetail(boardId)` 1회 호출** 후 확장카드를 연다
(`board_api_service.dart:99` 에 이미 있다).

이게 부수적으로 정확성 문제도 해결한다. **피드 응답은 서버에서 캐시된다** — 좋아요 수가
몇 분 묵은 값일 수 있고 `isLike` 는 응답에 아예 없다. 상세를 다시 받는 것이 맞다.

`BoardPost` → `MapPost` 변환은 `score: 0` 만 채우면 손실이 없다. 카드는 score 를 쓰지
않는다(마커 `globalZIndex` 전용).

### 한 경로로 통일한다

이미 마커로 로드된 글이면 `_postGroups` 에서 찾아 재사용해 API 를 아낄 수도 있다.
채택하지 않는다:

- 어떤 글은 좌우 스와이프가 되고 어떤 글은 안 되는 **비일관**이 생긴다.
- 피드 탭은 "이 글을 보겠다"는 의도다. "이 지역 글들을 훑겠다"(= 마커 탭)와 다르므로
  단일 카드가 오히려 맞다.
- `map_naver.dart` 복잡도를 감안하면 분기 없는 쪽이 안전하다.

구현:

- `_selectedGroupIndex`(마커용)와 **별도로** `_feedSelectedPost` 를 둔다 →
  `groups: [[post]]`, `initialGroupIndex: 0`
- `MapBottomCard` 에 `initialExpanded` 파라미터를 추가한다. 현재 확장 진입은 내부
  드래그/탭으로만 가능하다(`onExpandedChanged` 는 출력 방향 콜백일 뿐).
- 닫기: `onClose` → `_feedSelectedPost = null`. 마커 카드 경로의
  `_applySelectionHighlight(null)` / `_resumeAutomaticReloadsAfterInteractionClose()`
  는 **부르지 않는다** — 피드 카드는 마커를 선택한 적이 없고, 자동 재조회를 멈춘 적도
  없다(§3 참고).
- 상세 조회 실패 시: 카드를 열지 않고 스낵바로 알린다. 시트는 그대로 둔다.

## 6. 위치로 이동 — 주소 탭

확장카드는 이미 `streetName` 을 렌더한다(`map_card_expanded_content.dart:216-229`).
**그 주소 행을 탭 가능하게 만들고 옆에 이동 아이콘을 붙인다.** 아이콘이 "누를 수 있다"는
신호를 주면서 탭 영역은 주소 전체가 된다.

동작: **카드를 닫고** 그 좌표로 카메라 이동(줌 `kClusterExpandZoom` = 17.5).

피드 아이템에 `latitude`/`longitude` 가 있으므로 마커 존재 여부와 무관하게 이동할 수
있다. 이동 후 재조회로 그 지역 마커가 뜨고, 보고 싶으면 사용자가 탭하면 된다.

`onLocationTap` 콜백을 `MapBottomCard` → `MapCardExpandedContent` 로 내린다.

> 대안으로 "이동 + 그 마커 카드 자동 오픈"도 가능하지만, 마커가 아직 로드되지 않은
> 상태라 재조회 완료를 기다려 선택하는 비동기 체인이 붙는다. 지금은 이동까지만 하고
> 필요하면 나중에 얹는다.

## 7. 기존 마커 카드와의 공존 — 배타적

검색바가 이미 쓰는 패턴을 그대로 재사용한다:
`IgnorePointer(ignoring: _isAnyCardOpen)` + `AnimatedOpacity(opacity: _isAnyCardOpen ? 0 : 1)`.

추가로 마커 선택 시 컨트롤러를 peek 으로 애니메이트해, 다시 나타날 때 접힌 상태가 되게
한다.

Stack 순서상 **피드 시트를 마커 카드보다 앞에** 둔다(z-order 아래).

`_isAnyCardOpen` 은 피드 확장카드에도 걸려야 한다 — `_feedSelectedPost != null` 을
그 getter 에 포함시킨다. 그러면 피드 카드가 열린 동안 검색바·하단 버튼이 함께
페이드아웃되어 기존 마커 카드와 동일하게 동작한다.

## 8. 빈 결과·실패

**섹션이 0개면 시트를 아예 렌더하지 않는다.** peek 은 "올릴 게 있다"는 신호이므로
올릴 게 없으면 없는 것이 맞다. 실패도 같게 처리하고 `debugPrint` 만 남긴다.

내지도도 같은 방식이다 — `if (!_isLoading && _posts.isNotEmpty)` 로 시트 자체를 건다.

부수 효과로 **서버 구현 전까지 시트가 보이지 않는다.** 깨진 UI 가 노출되지 않는다.

## 9. 목 데이터 (서버 구현 전 UI 확인용)

서버가 붙기 전까지 화면을 볼 수 없으므로 목을 둔다. 원칙 두 개:

1. **목 JSON 을 실제 파서(`MapFeedResponse.fromJson`)에 태운다.** 목이 파서를 우회하면
   목으로 본 화면과 실서버 화면이 달라질 수 있다.
2. **릴리즈 빌드에 목이 새지 않는다.**

방법: `.env.local` 에만 `MAP_FEED_MOCK=true` 를 둔다. 릴리즈는 `.env.prod` 를 쓰고 그
파일에는 키가 없으므로 자동으로 false 다. 분기는 `getMapFeed()` 안 HTTP 호출 직전
한 곳뿐이다.

서버가 붙으면 `.env.local` 에서 키를 지우고, 목 파일을 삭제한다.
