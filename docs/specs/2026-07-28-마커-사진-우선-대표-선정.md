# 마커 사진 우선 대표 선정 + 지도 score 재조정

- 작성일: 2026-07-28
- 상태: 설계 확정
- 관련: `46cc2cb` [fix] 지도 마커 소실 — clearOverlays 대신 id별 deleteOverlay
- 영향 레포: `unimal-flutter` (메인 지도), `unimal-server` (board 모듈)

## 배경

마커 소실 버그(`46cc2cb`)를 조사하며 계측 로그를 넣는 과정에서, 마커 **그림 선정**에
별개의 결함 두 가지가 드러났다.

### 문제 1 — 사진 글을 올렸는데 점 마커로 보인다

같은 자리(11m 타일) 글들은 하나의 스택 마커로 묶이고, 그림·제목·카드 첫 장이 모두
**그룹 최고 score 글** 하나로 정해진다. 그 글이 사진 없는 텍스트 글이면 같은 그룹에
사진 글이 있어도 마커는 점으로 그려진다.

재현 조건 (실측 score 기준):

```
내 사진 글 (30분 이내, 참여 0) = 10000 + 1.0 + 3.0 = 10004.0
내 텍스트 글 (좋아요 2)        = 10000 + 0.1 + 4.0 = 10004.1  ← 대표를 가져감
```

11m 안에 참여도가 있는 내 텍스트 글이 있으면 방금 올린 사진 글이 점으로 표시된다.

### 문제 2 — 클러스터가 사진을 품고도 점으로 보인다

클러스터 빌더는 자식 마커 중 최고 score를 골라 그 아이콘을 쓴다. 본인글 +10000 때문에
방금 올린 텍스트 글(단독 마커)이 항상 뽑힌다.

2026-07-28 재현 로그:

```
[map] clusterBuilder top=5RqGNDo9 score=10001.0 count=7
[map] composeCluster applied topId=5RqGNDo9 count=7
```

사진 글 6개 + 텍스트 글 1개를 품은 클러스터가 **점 + `7` 뱃지**로 표시됐다. 줌아웃했을
때 그 동네를 대표하는 그림이 사진이 아니라 무의미한 점이 된다.

### 공통 원인

`score` 하나가 **랭킹**(크기 티어·zIndex·클러스터 대표 선정)과 **표시**(아이콘·캡션·
카드 첫 장)를 동시에 결정한다. 여기에 본인글 +10000 보너스가 얹혀 내가 올린 글이
어디서나 대표가 된다.

## 설계

### 1. 스택 그룹 — 랭킹과 표시를 분리한다

`lib/screens/map/map_naver.dart` · `_loadMapMarkersInternal`

그룹을 score 내림차순으로 정렬한 뒤, **사진 있는 글 중 최고 score를 맨 앞으로** 옮긴다.
이미 정렬돼 있으므로 `indexWhere(사진 있음)`가 곧 그 글이다. 사진 글이 없으면 그대로 둔다.

```dart
for (final list in grouped.values) {
  list.sort((a, b) => b.score.compareTo(a.score));
  final photoIdx = list.indexWhere((p) => p.fileInfoList.isNotEmpty);
  if (photoIdx > 0) list.insert(0, list.removeAt(photoIdx));
}
```

카드 스와이프 순서는 **대표만 앞으로 오고 나머지는 기존 score 내림차순을 유지**한다.
사진 글을 전부 앞으로 몰지 않는다.

랭킹에 쓰이는 score는 대표 글의 것이 아니라 **그룹 내 최댓값**을 쓴다. 정렬 직후 첫
원소가 최댓값이므로 대표를 옮기기 전에 확보한다.

| 값 | 기준 | 쓰이는 곳 |
| --- | --- | --- |
| 그룹 랭킹 score | 그룹 내 최댓값 | 티어 표본 `MarkerScoreTiers.fromScores()`, `tiers.sizeFor()`, `globalZIndex`, `tags['score']` |
| 표시 대표 | 사진 우선 (없으면 최고 score) | 아이콘, 캡션, 카드 첫 장, 탭 대상 |

티어 표본도 그룹 최댓값으로 만든다. 현재 `MarkerScoreTiers.fromScores(markerGroups.map((g)
=> g.first.score))`는 정렬 첫 원소를 쓰는데, 대표를 옮긴 뒤에는 그게 최댓값이 아니게 되므로
표본과 `sizeFor()` 인자를 함께 최댓값으로 바꿔야 한다.

그룹 최댓값은 마커 생성 시점까지 전달돼야 한다. 그룹 리스트만으로는 대표를 옮긴 뒤 최댓값을
복원할 수 없으므로 별도로 보관한다 (보관 방식은 구현 계획에서 정한다).

분리하는 이유: "이 자리가 얼마나 중요한가"와 "무엇을 보여줄까"는 다른 질문이다. 분리하지
않으면 참여도 높은 텍스트 글을 품은 스택이 대표가 바뀌면서 하위 티어(42dp)로 내려앉는다.

### 2. 클러스터 — 사진 자식을 우선한다

`lib/screens/map/map_naver.dart` · 마커 생성부 + `_buildClusterMarker`

클러스터 빌더는 자식의 `tags`만 볼 수 있으므로 판단 재료를 태그로 넘긴다.

```dart
tags: {
  'score': groupTopScore.toString(),   // 1번에서 그룹 최댓값으로 바뀜
  'title': derivedTitle,
  'canCard': canBecomeCard ? '1' : '0',
  'count': stackCount.toString(),
  'hasPhoto': topPost.fileInfoList.isEmpty ? '0' : '1',   // 추가
},
```

1번 수정 후 `topPost`는 이미 사진 우선 대표이므로, `hasPhoto`는 "이 그룹에 사진이 하나라도
있는가"와 같다.

선정 루프는 최고 score 자식과 사진 있는 자식 중 최고 score를 함께 추적하고, **사진 자식을
우선 쓰되 없으면 최고 score 자식으로 폴백**한다.

선정된 자식 기준으로 통일하는 항목:

| 항목 | 값 |
| --- | --- |
| 아이콘 (`_markerIconCache`, `_composeClusterIconAsync`) | 선정 자식 id |
| 캡션 | 선정 자식 `tags['title']` |
| 탭 시 카메라 이동 위치 (`info.size > 1`) | 선정 자식 `position` |
| 스택 여부 → 부채꼴 펼침 (`info.size == 1`) | 선정 자식 `tags['count'] > 1` |
| 텍스트 카드 줌 유도 (`info.size == 1`) | 선정 자식 `tags['canCard']` |
| `+N` 뱃지 숫자 (`totalCount`) | **전체 자식 `count` 합계 — 변경 없음** |

`info.size == 1`이면 자식이 하나뿐이라 선정 결과가 기존과 같다. 실질 변화는 `info.size > 1`
경로에만 생긴다.

### 3. 백엔드 — 본인글 보너스 제거, 신선도 가중치 상향

`unimal-server` · `board/.../map/MapBoardRepositoryImpl.kt`

```sql
-- 본인글 보너스 제거
- CASE WHEN b.email = :userEmail THEN 10000.0 ELSE 0.0 END

-- 신선도 배점 상향 (구간 경계는 유지)
  CASE
-   WHEN b.created_at >= NOW() - INTERVAL '30 minutes' THEN 1.0
-   WHEN b.created_at >= NOW() - INTERVAL '2 hours'    THEN 0.6
-   WHEN b.created_at >= NOW() - INTERVAL '6 hours'    THEN 0.3
+   WHEN b.created_at >= NOW() - INTERVAL '30 minutes' THEN 20.0
+   WHEN b.created_at >= NOW() - INTERVAL '2 hours'    THEN 8.0
+   WHEN b.created_at >= NOW() - INTERVAL '6 hours'    THEN 3.0
    ELSE 0.1
  END
```

`is_owner` 컬럼과 `:userEmail` 파라미터는 유지한다 — 마커 링 primary 색 판정과 `is_like`
계산에 계속 쓰이며 score와 무관하다.

**신선도 상향 이유.** 보너스만 제거하면 새 글 score가 `10004 → 4.0`으로 떨어져,
`ORDER BY score DESC LIMIT n`에서 밀려 방금 올린 글이 지도에 안 보일 수 있다. 조회 limit은
줌 12에서 30건, 줌 16에서 50건이다.

배점은 현재 실측 분포(`3.1 · 3.1 · 3.1 · 3.1 · 8.1 · 9.1 · 19.1 · 20.1 · 20.1 · 37.1`,
중앙값 8~9)에 맞춰 정했다.

| 글 | 새 score | 위치 |
| --- | --- | --- |
| 방금 올린 사진 글 (30분) | `20 + 3 = 23.0` | 상위권 |
| 2시간 된 사진 글 | `8 + 3 = 11.0` | 중상위 |
| 6시간 된 사진 글 | `3 + 3 = 6.0` | 중위 |
| 오래된 인기 글 (좋아요 17) | `0.1 + 3 + 34 = 37.1` | 1위 유지 |

새 글이 30분간 상위권에 올라 limit 컷을 통과하고, 시간이 지나면 자연스럽게 내려온다.
좋아요 10개면 참여도 높은 글이 새 글을 다시 앞선다. 내 글만이 아니라 남의 새 글도 함께
올라오므로 "지금 이 장소에서 있었던 사람들의 이야기" 컨셉과 맞다.

앱은 score를 숫자로만 쓰므로 프론트 변경이 필요 없다. 백엔드 단독 배포가 가능하다.

## 검증

1. `flutter analyze` 통과 (에러 0, 기존 이슈 50건 유지)
2. 같은 자리에 사진 글 + 텍스트 글을 두고, 텍스트 글의 score가 더 높은 상태에서
   마커가 **썸네일**로 그려지는지 확인 — `[map] stack group:` 로그로 그룹 구성 확인
3. 텍스트 단독 마커가 최고 score인 상태에서 줌아웃 시 클러스터가 **썸네일**로 그려지는지
   확인 — `[map] clusterBuilder top=` 로그의 선정 id가 사진 자식인지 확인
4. 참여도 높은 텍스트 글을 품은 스택의 마커 크기가 하위 티어로 떨어지지 않는지 확인
5. 백엔드 배포 후 방금 올린 글의 score가 `20 + 사진 3`으로 내려오는지, 지도에서 밀리지
   않는지 확인
