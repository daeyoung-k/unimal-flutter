# 텍스트 마커 2-레이어 말풍선 설계

- 작성일: 2026-07-19
- 상태: Phase 1~2 검증 완료·커밋(13892ec, 83cbd7e), Phase 3(레거시 정리) 구현 완료
- **⚠️ 후속 변경 있음 (2026-07-29) — §8 을 먼저 읽을 것.** 말풍선 아이콘 구성과
  점/캡션 숨김 방식이 바뀌었다. 본문 §3~§5 의 해당 서술은 당시 기록으로만 유효하다.
- 대상: `lib/screens/map/map_naver.dart`
- 우선 검증 플랫폼: iOS
- 선행 문서: `docs/specs/2026-07-17-텍스트-마커-로컬-전환-복구-design.md`
  (in-place·payload 재생성 시도의 실패 기록)

## 1. 목표

1. 점(일반 텍스트) ↔ 말풍선 마커 전환이 **부드럽게** 된다 (페이드).
2. 줌 인(17.3 이상)하면 말풍선 마커가 보인다.
3. 줌 아웃(16.8 미만)하면 점 마커로 돌아간다.

## 2. 확정된 제약 (2026-07-14 ~ 07-18 검증 결과)

이 설계는 아래 세 가지를 전제로 한다. 위반하는 구현은 채택하지 않는다.

- **C1. 클러스터러블 되돌림**: `NClusterableMarker`는 리클러스터링(카메라
  이동·줌·오버레이 추가)마다 최초 add payload 의 아이콘·크기·캡션으로
  leaf 를 다시 그린다 (iOS, flutter_naver_map 1.4.4, #276 유사).
  → 클러스터러블 마커에 대한 in-place `setIcon`/`setAlpha` 전환은 불가능.
- **C2. delete/add 핸들러 경합**: 플러그인 `deleteOverlay` 는 네이티브 ack
  이후 Dart 탭 핸들러를 제거하고 `addOverlayAll` 은 호출 즉시 등록한다.
  같은 id 를 await 없이 delete→add 하면 새 핸들러가 지워져 탭이 죽는다.
- **C3. 재조회 중 오버레이 추가 프리즈**: 재조회 진행 중 클러스터러블
  오버레이 추가가 네이티브 클러스터러의 dispatch_sync 와 겹쳐 앱 프리즈를
  재현한 이력 (2026-07-16). → 레이어 조작은 `_isLoadingMarkers` 중 금지.

## 3. 아키텍처: 2-레이어 분리

**점은 클러스터 세계, 말풍선은 일반 오버레이 세계.**

### 3.1 점 레이어 (기존 `NClusterableMarker`)

- payload 는 **영원히 점**. 텍스트 마커에 대한 표현 분기
  (`textCardMode`, `_textMarkerCardMode`, suppressBubble 빌드 분기)를
  updateMarkers 에서 **전부 삭제**한다.
- in-place 변경이 없으므로 C1 되돌림이 원천적으로 무의미해진다.
- 재생성은 스택 글 수 변화 등 기존 사유만 남는다.

### 3.2 말풍선 레이어 (신규, 일반 `NMarker`)

> 2026-07-19 공용화: 레이어 구현은
> `lib/screens/map/marker/bubble_marker_layer.dart` 의 `BubbleMarkerLayer`
> 로 추출됐고, 메인 지도와 내지도(my_story_map_screen)가 함께 쓴다.
> 화면은 목표 집합(`BubbleMarkerTarget`)만 계산해 `sync()` 에 위임한다.
> 내지도의 구 in-place 일괄 교체(`_applyTextCardMode`)는 같은 날 폐기.

- id: `bubble_{postId}` — 점과 다른 id 네임스페이스. 같은 id 재생성이
  없으므로 C2 경합 없음.
- 일반 NMarker 는 클러스터러가 관리하지 않으므로 **alpha 트윈이 안전**
  (C1 비적용). 부드러운 전환은 이 레이어에서만 수행한다.
- 아이콘: 기존 `_buildTextCardIcon` (카드 + 아래 점 앵커 합성) 재사용.
  말풍선의 점 그래픽이 밑의 점 마커를 정확히 덮는다.
- zIndex: `300000 + score` — 점 레이어(200000+score)보다 항상 위.
- 탭 리스너: 기존 단일 마커와 동일한 `_selectMarker` 흐름.

### 3.3 표시 규칙

- 전역 모드: 줌 히스테리시스 유지 — 진입 `17.3`, 이탈 `16.8`
  (`TextMarkerPresentationPolicy` 재사용 가능).
- 말풍선 대상: 사진 없는 텍스트 글 + 단일 그룹 + 비밀집(dp 기준) +
  바텀 카드 억제 아님 (기존 규칙 그대로).
- 말풍선 목표 집합 = 전역 모드가 카드일 때의 eligible 집합. 아니면 공집합.

### 3.4 동기화 (단일 경로)

`_syncBubbleLayer(rawZoom, latitude)` 하나로 수렴:

1. 히스테리시스로 전역 모드 갱신
2. `_isLoadingMarkers` 면 반환 (C3) — 재조회 종료 후 수렴 패스가 재호출
3. 목표 집합 계산 → 현재 표시 집합과 diff
4. 추가분: 아이콘 비동기 생성 → 세대 검증 → `addOverlayAll`(alpha 0)
   → 페이드 인
5. 제거분: 페이드 아웃 → `deleteOverlay`

트리거: ① `_onCameraIdle` ② 재조회 성공 직후 1회 ③ 카드 닫힘 복원.
셋 다 같은 함수. 불일치 없으면 no-op.

### 3.5 경합 방어

- 표현 세대(latest-wins): 카메라 이동·새 sync 시작마다 증가, 비동기
  아이콘 완료 시 검증 후 폐기.
- 페이드 타이머: id 별 1개, 재전환 시 이전 타이머 취소 후 현재 alpha 에서
  이어서 진행 (사라지는 중 → 다시 나타나기 자연스럽게).
- 재조회로 글이 사라지면(뷰포트 이탈·삭제) 해당 말풍선도 제거.
- 다크모드 forceRebuild 시 말풍선 레이어도 전체 재구성.

### 3.6 카드 열림 억제 (Phase 3)

- 카드 열림: 말풍선 레이어 페이드 아웃 → 삭제 (점은 원래 항상 있으므로
  별도 복원 상태·restoreIds 불필요 — 기존 `_syncTextBubbleSuppression`
  의 in-place 억제/복원 로직 대체 가능성 검토).
- 카드 닫힘: `_syncBubbleLayer` 재호출로 현재 줌 기준 재구성.

## 4. 오류 처리

- 아이콘 생성 실패: 해당 글 말풍선 생략(점은 그대로 보임) — 마커 소실 없음
- addOverlayAll 실패: 표시 집합 미갱신 → 다음 sync 가 재시도
- 세대 불일치: 오류 아님, stale 폐기

## 6. 단계별 구현 계획

각 Phase 끝마다 사용자 실기기 검증 후 다음 단계 진행. 커밋은 승인 후.

- **Phase 1 — 전환 신뢰성**: 말풍선 레이어 추가/제거 (애니메이션 없음).
  updateMarkers 의 텍스트 카드 분기 제거. 검증: 17.3/16.8 전환, 같은 API
  줌 구간 전환, 빠른 줌 반복, 탭 동작, 재조회 후 유지.
- **Phase 2 — 부드러움**: 페이드 인/아웃(kBubbleFadeDuration 200ms).
  충돌 숨김(Q1)은 페이드와 교차 — 인 완료 후 켜고, 아웃 시작 전에 꺼서
  점이 말풍선 밑에서 자연스럽게 나타나고 사라진다. 페이드 아웃 중 재목표
  시 취소 후 현재 alpha 에서 복귀. 탭 우선순위 확인(Q2)은 실기기.
- **Phase 3 — 레거시 정리 (완료)**: 카드 열림 억제/닫힘 복원은 Phase 1~2
  에서 말풍선 레이어 sync 로 이미 대체됨. in-place 전환·억제 경로 전체 삭제
  (`_flipTextMarkerModeInPlace`, `_fadeInMarker`/`_alphaTweens`,
  `_syncTextBubbleSuppression`, `_restoreTextBubblesAfterClose`,
  `_textBubbleRestoreIds`, `_textMarkerCardMode`, `_isDisplayedAsCard`).
  재도입 금지 계약 테스트 추가.

2-레이어 구조 자체(점 = 클러스터러블 상주 / 말풍선 = 일반 NMarker 동적 추가·삭제,

관련 커밋: `c3db005` [feat] 텍스트 마커 점 표현 정리 / `c758189` [fix] 제목 중복

### 계기 — 점이 두 개였고 크기가 달랐다

줌 16.3~16.8 경계에서 텍스트 마커의 원 크기가 튀었다. 원인:

| | 원 지름 |
| --- | --- |
| 점 마커 (score 위계 42/50/58/66) | 38.6 ~ 60.7dp |
| 말풍선 아이콘 안에 합성된 점 | **32dp 고정** |

말풍선이 뜰 때 `isHideCollidedMarkers` 로 밑의 점을 가렸으므로, 전환 순간 원이
46→32dp(기본 티어) 또는 60.7→32dp(핫플)로 축소돼 보였다.

> 이 문서 §5 의 폴백 메모가 이미 같은 문제를 지적하고 있었다 — *"큰 티어 66dp
> 점은 글리프(39dp) 밖으로 살짝 보일 수 있음"*. 당시엔 폴백 시의 부작용으로만
> 적혔지만, 실제로는 기본 경로에서 크기 점프로 드러났다.

### 변경 1 — 텍스트 마커를 score 크기 위계에서 제외

`kTextDotMarkerSize`(≈34.78dp) 고정. 34.78 인 이유는 `createTextDotImage` 가
200px 캔버스에 32dp 프레임을 그려 원이 캔버스의 92%(184/200)만 차지하기 때문 —
화면상 원 지름을 32dp 로 만들려면 그 비율을 되돌려야 한다.

크기를 되돌리는 경로를 **모두** 같은 규칙으로 맞춰야 한다(한 곳만 놓치면 줌
왕복에서 다시 튄다): 마커 생성, 클러스터 빌더 `size==1` 복원, 스택 부채꼴 마커,
내지도(`my_story_map_screen`)의 마커 생성·클러스터 빌더.

### 변경 2 — 말풍선 아이콘에서 점을 뺐다

아이콘 = 카드 + 하단 **투명 여백**(`kTextBubbleDotReserve` = 32+4 = 36dp).
그 자리에 **항상 켜져 있는 실제 점 마커가 그대로 보인다.**

- 점이 하나뿐이므로 두 그림의 크기를 사람이 맞춰야 하는 불변식이 사라진다.
- 페이드 200ms 동안 점이 두 개 그려지던 것(가림은 페이드 완료 후에 켜지므로)도
  없어진다.
- 이에 따라 말풍선의 `setIsHideCollidedMarkers` 는 **false 고정**이다.
  참조가 0이 된 `TextDotGlyph`/`_TextDotPainter` 는 삭제했고, 점 기하는
  `paintTextDot` 이 단일 소유한다.

**대가**: 204dp 카드와 겹치는 다른 마커가 정리되지 않아 그대로 보인다. 말풍선
대상이 "단일 + 비밀집(120dp 내 이웃 2개 미만)"으로 제한돼 빈도가 낮다는 판단으로
완화 없이 수용했다. 거슬리면 `kTextCardDenseNeighbors` 를 조인다.

### 변경 3 — 점의 제목 캡션은 네이티브 줌 범위로 끈다

변경 2로 마커를 가리지 않게 되자 캡션 억제가 `isHideCollidedCaptions`(충돌 판정)
에만 의존하게 됐다. **그런데 기하가 맞지 않는다** — 두 마커 모두 앵커 (0.5,1.0)
이라 아이콘은 좌표 **위쪽**으로 뻗고 캡션은 마커 **아래쪽**에 그려져 겹치지
않는다. 그러면 제목이 카드와 캡션에 두 번 보인다. (이전에 캡션이 사라진 건
마커 자체가 숨겨져 딸려 사라진 것이었고, 충돌 판정이 동작해서가 아니었다.)

→ `NOverlayCaption(maxZoom: kTextCardEnterZoom)` 으로 네이티브가 끈다. 선언적이고
상태 동기화도 in-place 변경도 없어 결과가 확정적이다.

- 사진 글에는 걸지 않는다(말풍선이 뜨지 않음).
- **선택 마커의 전체 타이틀 캡션(`_selectedCaption`)에도 걸면 안 된다** — 줌 19
  에서 선택 시 타이틀이 사라진다.
- `exit(16.3)` 이 아니라 `enter(16.8)` 를 쓴다: exit 로 잡으면 기본 진입 줌
  16.5 에서 캡션이 사라져 기본 화면이 망가진다.
- `BubbleMarkerLayer` 의 캡션 숨김 토글(`_setCaptionHiding`)은 제거. 남은
  `setIsHideCollidedCaptions(true)` 는 빌드 시 1회이며 용도가 바뀌었다 —
  "카드와 겹치는 **다른** 마커의 캡션" 정리 전용이다.

**대가**: `maxZoom` 은 임계값이 하나라 말풍선의 히스테리시스를 따라가지 못한다.
줌아웃 하강 중 16.3~16.8 구간에서 카드와 캡션이 함께 보인다.

### 검토했고 배제한 대안

같은 문제를 다르게 풀 수 있는지 여러 갈래를 따졌고, 아래는 모두 기각했다.
다시 제안될 만한 것들이라 이유를 남긴다.

- **점 마커를 없애고 말풍선으로 통일** — 클러스터링을 잃는다(점은 클러스터러블,
  말풍선은 `kBubbleMinZoom` 으로 클러스터링 구간에서 차단). 통일 마커를
  클러스터러블로 만들면 C1 이 되돌아온다. 점 비트맵은 프로세스당 1회 캐시되는데
  말풍선은 글마다 개별 렌더라 콜드 스타트가 나빠지고, 200x200 규격에 맞춘
  +N 뱃지 합성이 깨진다. 스택/밀집 표현이 필요해 결국 점 변형을 다시 만들게 된다.
- **말풍선을 미리 만들어 두고 가시성만 토글** — `setIsVisible(false)` 로 미리
  숨겨 add 하는 패턴은 로컬 dedupe 로 숨김이 무효화된 이력이 있다(2026-07-14).
- **말풍선을 상주시키고 네이티브 `minZoom` 으로 줌 표시 제어** — `setIsVisible`
  이력은 이 방식엔 해당하지 않고(이 프로젝트가 `kBubbleMinZoom` 으로 이미
  의존한다) 기술적으로 가능하다. 그래도 기각: 네이티브 줌 숨김은 하드 컷이라
  **페이드가 사라지고**, 임계값이 하나라 **히스테리시스가 사라져** 16.8 파킹 시
  204dp 카드가 깜빡인다. 게다가 말풍선 표시 조건 중 밀집(줌 의존)·바텀 카드
  열림·재조회 중은 줌으로 표현할 수 없어 `_syncBubbleLayer` 가 그대로 남는다 —
  두 메커니즘이 같은 가시성을 다투게 되므로 단순해지지 않는다.
- **캡션을 `setCaption` 으로 직접 끄기** — 클러스터러블 in-place 변경(C1) +
  상태 동기화 부활.
- **캡션 페이드** — `NOverlayCaption` 에 alpha 필드는 없지만 `color`/`haloColor`
  의 alpha 채널로는 가능하다. 그러나 `onCameraChange` 가 카메라 위치를 넘기지
  않아 프레임마다 `getCameraPosition()` async 왕복이 필요하고, 거기에 마커 수만큼
  `setCaption` 이 붙는다(20개 × 60fps ≈ 초당 1,200회 채널 호출). 8자 텍스트를
  부드럽게 하려고 치를 비용이 아니다.
