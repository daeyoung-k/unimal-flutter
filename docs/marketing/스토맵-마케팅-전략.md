# 스토맵 마케팅 전략

> 살아있는 문서. 자동화 태스크 3종(커뮤니티 스캔·콘텐츠 초안·주간 리포트)이 이 문서를 읽고 초안을 만든다.
> 방향이 바뀌면 이 문서만 고치면 자동화 결과물이 따라온다.
> 최초 작성: 2026-08-20

## 1. 포지셔닝

**한 줄:** "지도 위에 남기는 이야기 — 이 장소에서 있었던 사람들의 이야기를 발견하는 지도 SNS"

- 경쟁 앱(어디, 오늘의커밋, 맵모, 트래버리, Place+)은 전부 **혼자 쓰는 기록 도구**다.
- 스토맵의 차별점은 **발견(소셜)**: 내 이야기가 지도 위에서 남에게 발견되고, 나도 이 장소의 다른 이야기를 발견한다.
- 메시지에서 "일기/기록 앱"보다 "**이 장소의 이야기**"를 앞세운다. 기록 앱으로 분류되는 순간 기능 비교 싸움이 된다.

## 2. 타겟

| 순위 | 타겟 | 훅 |
|------|------|-----|
| 1 | 일상 기록 남기는 2030 (카페·맛집·산책) | "내 동네가 내 일기장이 된다" |
| 2 | 여행 기록 유저 | "여행 경로가 지도 위 스토리로 남는다" |
| 3 | 커플·친구 | "우리가 갔던 곳들" — 친구 기능 출시 후 본격화 |

## 3. 채널 우선순위

| 채널 | 역할 | 리듬 | 비고 |
|------|------|------|------|
| 스레드(Threads) | 빌드로그 + 제품 소식. 한국 인디 개발 씬 활발, 도달 효율 높음 | 주 3~5회 짧은 글 | **메인 채널** |
| 디스콰이엇 | 런칭·메이커로그·피드백. 투자/네트워크 부수 효과 | 주 1회 메이커로그 | 커뮤니티 가이드 준수 |
| 네이버 블로그 (본인 계정) | SEO — "장소 기록 앱" 류 검색 유입 | 주 1회 | 자동 포스팅 절대 금지, 직접 게시 |
| 커뮤니티 답글 | 수요가 이미 있는 스레드에 맥락 맞는 답글 | 매일 스캔, 맞는 곳만 | 아래 규칙 필수 |
| 인스타그램 | 지도/스크린샷 비주얼 | 여유 있을 때 | 후순위 |

## 4. 콘텐츠 필러

1. **빌드로그** — 직장인 + 평일 저녁 1인 개발 여정. 솔직한 지표 공유, 기술 선택 이야기(MSA·Kafka 등은 개발자 타겟), 실패담. 스레드·디스콰이엇용.
2. **프로덕트** — 기능 소개, 업데이트 소식, Android 베타 진행 상황.
3. **사용 시나리오** — 데이트 코스 기록, 여행 지도 만들기, 동네 탐험. 블로그 SEO용.

## 5. 커뮤니티 답글 규칙 (밴 방지 — 반드시 준수)

- 게시 전 해당 커뮤니티의 **홍보 규정 확인**. 홍보 금지 커뮤니티면 게시하지 않는다.
- **개발자 신분을 밝힌다**: "제가 만들고 있는 앱이라 참고로만 봐주세요" 식.
- 질문에 스토맵이 **실제로 답이 되는 경우만**. 복붙 금지, 스레드 맥락에 맞춰 새로 쓴다.
- 같은 커뮤니티에 주 1회 이하. 도배 금지.

## 6. 운영 리듬

| 주기 | 자동 (스케줄러) | 수동 (본인) |
|------|----------------|-------------|
| 매일 | 커뮤니티 스캔 + 답글 초안 → `community/` | 확인 5분, 맞는 곳 1개 이하 답글 |
| 화·금 | 콘텐츠 초안 (스레드 2 + 디스콰이엇 1 + 블로그 1) → `drafts/` | 검토 후 게시 10분 |
| 월 | 주간 리포트 (언급·경쟁·키워드) → `reports/` | 읽고 이번 주 방향 조정 |

## 7. 지표 (주간 체크, 수동)

스토어 페이지 조회 → 다운로드 전환율, 신규 가입 수, 게시글 작성 수, DAU. App Store Connect / Play Console에서 확인. (추후 자동화 후보)

## 8. 하지 않는 것

- **어떤 형태든 자동 게시·매크로** — 계정 밴 + 네이버 저품질 + 브랜드 손상. 모든 글은 사람이 검토 후 직접 게시한다.
- 무관한 스레드 도배, 맞팔·품앗이.
- 일반 사용자 후기로 위장한 홍보 (기만 마케팅).
